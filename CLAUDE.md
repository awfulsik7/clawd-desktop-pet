# Claw'd на рабочем столе — памятка для доработки

Питомец для Windows: прозрачное окно поверх всех, в котором кодом нарисован пиксельный Claw'd. Вся программа — один файл [Clawd.cs](Clawd.cs). Картинок, зависимостей и проектных файлов нет.

## Сборка и запуск

```bash
powershell -ExecutionPolicy Bypass -File build.ps1
```

Скрипт вызывает `csc.exe` из .NET Framework 4, который есть в любой Windows. Отсюда главное ограничение: **язык — C# 5**. Нельзя: `$"..."`, `?.`, `nameof`, `out var`, члены через `=>`, кортежи, `async Main`. Пиши `string.Format`, явные проверки на `null`, `delegate { }`.

`Clawd.exe` во время работы заблокирован, сборка поверх него молча не пройдёт. Перед сборкой:

```bash
powershell -Command "Get-Process Clawd -ErrorAction SilentlyContinue | Stop-Process -Force"
```

Запуск без аргументов включает питомца, повторный — выключает. Запуск с аргументами передаёт команду уже работающему и сразу выходит.

## Как проверять без мышки

Мышкой из терминала питомца не потаскать, поэтому всё проверяется командами и дневником.

```bash
./Clawd.exe --state coffee
```

```bash
./Clawd.exe --say "текст"
```

```bash
./Clawd.exe --drop 800,600
```

`--drop X,Y` отпускает питомца ногами в пикселе экрана, как после перетаскивания. После этого его положение читается из прямоугольника окна: ноги находятся на `Top + 40 + 14*U` (по умолчанию `U = 6`, то есть `Top + 124`), центр — на `Left + 140`.

Дневник бросков включается переменной окружения и пишет, что нашлось под питомцем и почему он сел, повис или упал:

```bash
CLAWD_LOG=drops.log ./Clawd.exe
```

**`--drop` не заменяет настоящий бросок мышкой.** При команде окно питомца в момент запроса ещё стоит в старом месте, при перетаскивании — уже в новом. Так однажды прошёл незамеченным баг, из-за которого он находил под собой самого себя. Если меняешь логику броска, попроси человека потаскать и прочитай дневник.

## Устройство файла

| Что | Роль |
|---|---|
| `Native` | Объявления Win32 |
| `St` | Состояния питомца: `Idle`, `Walk`, `Sit`, `Code`, `Hang`, … |
| `Log` | Дневник бросков |
| `Activity` | Фоновый поток: что играет, какое окно впереди, как давно трогали мышь. Выдаёт `Ctx` |
| `ElementTracker` | Фоновый поток: ищет элемент интерфейса под точкой через UI Automation и следит, куда он уехал |
| `PetView` | Только рисование: спрайт, предметы, частицы, облачко |
| `Pet` | Окно и всё поведение: физика, перетаскивание, выбор следующего действия, меню, команды |
| `Program` | Один экземпляр, приём команд от повторных запусков |

`Pet.Tick()` вызывается на каждый кадр экрана. Он двигает окно каждый кадр, а перерисовывает спрайт 24 раза в секунду или при смене состояния — иначе программа съедает треть ядра процессора.

Координаты питомца (`x`, `y`) — это точка между ногами, в единицах WPF (DIP). Win32 и UI Automation отдают физические пиксели; перевод — через `sx`, `sy`.

## Как добавить анимацию

Нужно пройти шесть мест. Пропустишь одно — состояние либо не нарисуется, либо в него нельзя будет попасть.

1. `enum St` — новое имя.
2. `PetView.DrawSprite` — поза: тело, лапки, глаза. Если питомец сидит, добавь состояние в `sitting`.
3. `PetView.DrawProps` и `DrawParticles` — предмет в лапках и летающие частицы, если они есть.
4. `Pet.Command` — строка `else if (arg == "имя") Set(St.Имя, секунды);`.
5. `Pet.StateNames` — пара «имя команды, подпись в меню».
6. `Pet.ChooseNext` — с какой вероятностью питомец делает это сам.

Реплики лежат в массивах вроде `CodeLines` — русский набор и английский, по порядку. Периодические реплики состояния назначаются в конце `Tick`.

Чтобы состояние включалось само, когда человек чем-то занят, добавь значение в `Ctx`, условие в `Activity.Poll` и соответствие в `Pet.ContextState`.

### Правила рисования

Спрайт лежит на сетке 18×14 клеток (`Cols`, `Rows`), клетка — `U` пикселей. Мелкие детали — на половинах клетки.

- `R(dc, кисть, x, y, w, h)` — прямоугольник в клетках.
- `G(dc, кисть, x, y, строки)` — маленький рисунок из строк, где `#` — закрашенная половинка клетки.
- `Limb` и `Torso` рисуют часть тела сразу с тенью.
- `Rising` — частица, которая всплывает и гаснет.

Тело занимает столбцы 3–15, глаза стоят в столбцах 5 и 12, ноги — 4, 6, 11, 13. Стоя верх тела на строке 4, сидя — на строке 6. Предмет перед сидящим питомцем начинай не выше строки 10,5, иначе он закроет глаза.

Все координаты округляй до половины клетки: рисование идёт без сглаживания, и дробные значения дают неровные пиксели.

## Игры и мышка

Игры запускаются из меню «Игры» и командами `--state ball | throw | juggle | hide | tag | react | rock | scissors | paper`. `throw` бросает мяч сам, без мышки, — так проверяется погоня целиком.

- **Мяч** — отдельное окно `BallWindow`; его физику считает `Pet.TickBall`. Состояния мяча — `BallSt`.
- **Прятки** рисуют питомца обрезанным (`PetView.Peek`): видно только то, что торчит над краем, за которым он сидит.
- **Карточка над головой** (`PetView.Sign`) общая для «камень, ножницы, бумага» и сигнала в игре на реакцию.
- **Поглаживание и подножка** — `Pet.TickTouch`. Гладить — три разворота курсора над головой. Подножка — только резкий горизонтальный взмах по ногам: скорость усредняется по нескольким кадрам, порог 2000 DIP/с. Это проверяется только живой мышкой.
- **Отпрыгивание при печати** — `Pet.TickTyping`. Положение текстового курсора читает `Activity.ReadCaret`; сами клавиши программа не смотрит.

Любое новое состояние-игру добавь в списки исключений в `TickTouch`, `UpdateContext` и в проверку перед зарядкой в `Tick`, иначе питомец посреди игры наденет наушники или пойдёт делать зарядку.

## Что легко сломать

- **Питомец находит самого себя.** UI Automation считает окно питомца сплошным, даже там, где оно прозрачное. Поэтому на время перетаскивания и запроса окну ставится `WS_EX_TRANSPARENT` (`SeeThrough`). Обязательно снимай его обратно, иначе питомца нельзя будет схватить; на этот случай в `Tick` есть страховка по времени.
- **Chrome отвечает точно со второго раза.** На первый запрос о точке он возвращает «всю страницу», на повторный — настоящий элемент. `ElementTracker` спрашивает каждую точку дважды. Первый запрос после запуска занимает секунды, поэтому есть прогрев при старте и во время перетаскивания.
- **Блоки разметки — не элементы.** Колонка страницы формально элемент, но сидеть «на ней» значит сидеть где угодно. Фильтр по типу и размеру — в `ElementTracker.Find`. Он подобран на глаз.
- **Запросы к чужим приложениям только из фонового потока.** Приложение может не отвечать, а `Tick` обязан уложиться в кадр.
- **Видимость окна проверяй через `VisibleAt`**, а не по порядку окон: прозрачные полноэкранные накладки (оверлеи игр, запись экрана) стоят выше всех и ничего не закрывают.
- **Облачко у края экрана.** Окно шире спрайта, чтобы облачко помещалось; у верхнего края экрана оно рисуется под питомцем (`Below`).

## Сайт и выпуск

Лендинг — один файл [docs/index.html](docs/index.html), публикуется GitHub Pages из папки `docs` ветки `main`. `Clawd.exe` в репозиторий не кладётся: он выходит через Releases, и кнопка на сайте ведёт на `releases/latest/download/Clawd.exe`.

Новая версия:

```bash
gh release create v1.1.0 Clawd.exe --title "Claw'd 1.1" --notes "что изменилось"
```

Проект неофициальный. Пометка об этом стоит на сайте и в README — не убирай её и не добавляй в репозиторий логотипы или шрифты Anthropic.
